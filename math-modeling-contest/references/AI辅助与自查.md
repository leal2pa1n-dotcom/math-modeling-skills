# AI 辅助工作流与 AI 痕迹自查（蒸馏自抖音方法论）

> 本文是可直接执行的浓缩版（整合自抖音数模方法论与 AI 论文自查表）。

## 一、AI 正确用法（五法则）

| 法则 | 说明 |
|------|------|
| 给角色 | "你是 XX 专家" 比 "帮我 XX" 效果好 10 倍 |
| 给约束 | 字数、格式、输出要求越具体越好 |
| 给上下文 | 数据维度、已选方法、当前进度都告诉它 |
| 分步骤 | 复杂任务拆多步，别一个 Prompt 塞所有 |
| 要求解释 | "为什么推荐这个方法" 比 "推荐一个方法" 更有价值 |

**分阶段 Prompt**：读题（贴原文+判题型+列3方向+问坑）→ 建模（给方法名+完整推导+物理意义+前提假设+失效条件）→ 编程（数据特征+正负向+打印中间结果）→ 写作（学术语体+保留数字公式+每段主题句+不新增数据）。

## 二、AI 的幻觉陷阱（永远验证）

| 幻觉类型 | 表现 | 应对 |
|---------|------|------|
| 编造文献 | 不存在的引用 | 每条去知网/数据库搜 |
| 编造公式 | 推导中系数错 | 手算小例子验证 |
| 编造数据 | 捏造精度数字 | 追溯数据来源 |
| 混淆概念 | 相似方法搞混（灰色预测 vs 灰色关联） | 要求分别说明原理与场景 |

## 三、AI 高频错误清单

### 代码层
数据维度错误（行列搞反→NaN）、公式实现错误（符号/系数）、标准化方向错误（按行 vs 按列）、索引偏移（从0开始差一位）、结果未排序、数据泄漏（用未来预测过去）。

### 建模层（更隐蔽）
方法与数据量不匹配（20 样本上深度学习）、忽略前提假设（非正态上参数检验）、过度复杂化、指标方向搞混、混淆相似方法、忽略异常值。

### 论文层（评委一眼看穿）
**假设前后对不上、自编文献和结论、数据来源捏造。**

## 四、交稿前自查清单

按以下维度逐项核对，全部通过才可提交：

**假设与逻辑一致性**
- [ ] 模型假设前后无矛盾，每个假设都有对应使用场景
- [ ] 结论由本文结果支撑，无凭空引申
- [ ] 各问之间的逻辑链条连贯

**文献与数据真实性**
- [ ] 每条参考文献真实存在（可检索到）
- [ ] 每个数据有来源（附件/实测/公开数据集），无捏造
- [ ] 数字可复现（代码能跑出同结果）

**公式与代码正确性**
- [ ] 每个公式手算小例子验证过
- [ ] 代码打印中间结果，已核对数量级/单位/指标方向
- [ ] 无数据泄漏（训练/测试集划分干净）

**模型与数据匹配**
- [ ] 方法满足数据的前提假设（分布/样本量/删失/不均衡）
- [ ] 简单基线已做，复杂方法有对比价值
- [ ] 评价指标与目标对齐（不均衡别只盯 AUC）

**工程与格式**
- [ ] 公式前后有文字说明，图表编号齐全
- [ ] 摘要含关键数字，关键词规范
- [ ] 可编译（LaTeX→PDF 无报错）

> 工具化提示：可用豆包/大模型按「26 维 AI 自查表」做深度自查——上传论文+真题+附件+自查表，指令「请帮我基于 AI 自查表对该数学建模竞赛论文进行深度自查，并根据自查结果输出 AI 自查结果表」。改完重复自查，全部合格才交。

## 五、用 AI 的分环节红线与六条提示词（云顶数模 20 天计划）

| 环节 | 红线 |
|------|------|
| 文献 | 先问「这类题常用什么方法」，再拿关键词去知网/GoogleScholar。**不要让模型直接列参考文献，它会编** |
| 代码 | 第一版当草稿。用已知结果对一下，极端值、量纲、能不能复现，三件事不过关别进论文 |
| 写作 | 骨架和论点自己写，AI 扩写润色。摘要可让它按评委标准挑套话，改不改你定。整篇交给它，读起来像同一段话复制二十遍 |
| 假设 | 让 AI 列候选假设并标风险，高风险那几条论文里必须做灵敏度。AI 给的拆题当讨论起点，不当最终结构 |
| 分工 | 建模手拍板模型，编程手对数字负责，写作手从第一小时搭架子。三个人都要读题，评委只看论文 |

**六条提示词**（每条写明「AI 给选项，人拍板」）：拆题、假设风险表、代码核查、摘要挑毛病、符号一致性、模拟评委。
