# 现代数模工作流与工具链（两条路线融合）

> 来源：对 C038（复杂约束+不确定性+运筹优化）与 C132（统计+机器学习+生存分析+决策优化）两篇论文的进阶拆解。本文件是「如何把获奖论文做得更好」的升级框架。

## 一、两条路线的共同核心

两篇论文表面差异大，但共同核心不是「用了高级算法」，而是把实际问题**逐层转换**：

> **数据理解 → 机制/统计分析 → 数学模型 → 算法求解 → 稳健性验证 → 决策输出**

具体到四问的结构（两篇通用）：

- **问题一** → 认识变量（建立关系模型）
- **问题二** → 处理不确定性（从确定 → 随机/风险）
- **问题三** → 处理变量之间的关系（相关性 → 约束）
- **问题四** → 做决策/分类
- **结尾** → 用敏感性分析证明模型可靠

## 二、两条路线对照

| | 路线一（C038 农作物） | 路线二（C132 NIPT） |
|---|---|---|
| 本质 | 多周期、强约束、离散/连续混合的资源配置优化 | 统计 + ML + 生存分析 + 优化 + 集成的混合数模 |
| 决策变量 | Binary/Continuous/Integer 混合 | 分组边界 + 检测时点 + 二分类 |
| 核心升级 | 确定性 LP → CVaR 随机风险优化 | 简单回归 → GPR/深度生存网络/堆叠集成 |
| 求解 | 手写 DEGA → 应换精确求解器+pymoo | GA 全局优化 / LightGBM+Optuna |

## 三、「如何做得比论文更好」的关键升级点

### 1. 不要一上来就 DEGA（路线一）
先判断问题**究竟属于哪一类**：决策变量有 Binary/Continuous/Integer 混合 → 很可能是 **MILP/MINLP/MIQP/多目标随机优化**，不是「遗传算法问题」。

正确顺序：
```
确定性 MILP → Gurobi/OR-Tools 求精确最优解(Baseline)
→ 加入随机变量 → Scenario Generation → Monte Carlo → CVaR
→ 多目标 → NSGA-II/III → 与 Gurobi/DE/PSO/GA 对比 → 敏感性/鲁棒性
```
这样能证明「Exact solver 结果是什么 + 元启发式能否在合理时间逼近最优」，比单独报「DEGA 得 XX 万元」可信得多。

### 2. CVaR 升级为 Pareto 前沿（路线一）
问题二、三已迈进正规风险优化（`max E[Profit] − λ·CVaR_α(Loss)`），但更完整：
```
随机变量建模 → Distribution fitting → Monte Carlo / Latin Hypercube
→ Scenario-based optimization → Expected Profit + CVaR + Worst Case → Pareto Frontier
```
不要只给「考虑风险后利润下降」，要画**收益-风险 Pareto 前沿**让决策者看权衡。

### 3. 不能把 99.7% 准确率当强模型证明（路线二）
医学异常识别天然**类别不平衡**（正常 99% / 异常 1%），全预测「正常」也有 99% 准确率。必须加：
ROC-AUC、PR-AUC、Sensitivity/Recall、Specificity、F1、MCC、Calibration、Brier Score、Confusion Matrix。**重点看 Recall/Sensitivity**（漏掉异常代价远高于误报）。

### 4. 生存分析不要直接跳 DeepHit（路线二）
重实现顺序应是 `Cox baseline → Random Survival Forest → DeepHit → MLP/LSTM+DeepHit`，这样才能回答「复杂模型到底比简单模型提升多少」。

## 四、现代工具链（分层）

```
数据层: pandas / numpy / scipy / openpyxl / polars(大数据)
EDA/可视化: matplotlib / seaborn / plotly / scipy.stats / statsmodels
统计层: statsmodels(OLS/GLM/MixedLM/GEE)  ·  PyMC(贝叶斯)
GPR: scikit-learn GPR  ·  GPy  ·  GPflow
生存: lifelines(KM/Cox/Weibull/AFT)  ·  pycox(DeepHit/Cox-Time/LogisticHazard/PMF)
机器学习: scikit-learn / LightGBM / XGBoost / CatBoost
调参: Optuna(搜索/pruning/多目标/并行)
优化: Gurobi(LP/MILP)  ·  OR-Tools(CP-SAT/调度/路径)  ·  Pyomo(模型求解器解耦)  ·  pymoo(GA/DE/NSGA-II/III/MOEA-D/CMA-ES/PSO)
不确定性: 分布拟合 / Monte Carlo / Latin Hypercube / Scenario Generation / CVaR / Chance Constraint
可解释: SHAP / Permutation Importance / Partial Dependence / Feature Interaction
验证: Bootstrap / 交叉验证(嵌套CV) / Monte Carlo / 极端情景 / 消融实验
```

## 五、9-Phase 现代工作流

```
Phase 0 题目审计: 变量/单位/决策变量/目标/约束/不确定变量/时间关系/数据质量
Phase 1 数据工程: data/{raw,cleaned,processed,external}
Phase 2 EDA: 缺失/异常/分布/相关性/重要性/趋势/组间差异 → figures/ tables/
Phase 3 Baseline: 每个复杂模型前放 Linear/RF/Logistic/Cox/MILP/Simple GA，算 Improvement%
Phase 4 数学模型: 按题分流(资源配置→LP/MILP/MIQP；组合→CP-SAT/GA/DE/PSO；多目标→NSGA-II/III)
Phase 5 不确定性: 分布拟合→相关结构→Monte Carlo/LHS→Scenario→Stochastic Opt→CVaR/Chance Constraint
Phase 6 算法竞争: 多算法对比表(最优值/均值/方差/时间)，证明算法有效
Phase 7 验证: 参数/算法敏感性、Bootstrap、嵌套CV、极端情景、消融实验
Phase 8 可解释性: SHAP/Permutation/PD，回答「为什么」
Phase 9 论文输出: 模型→result.csv→自动生成图/表/指标/LaTeX→论文(不手工复制数字)
```

## 六、获奖优先级（比赛导向，非科研）

1. 数学结构是否漂亮
2. 模型能不能解释
3. 求解是否稳定
4. 有没有对比实验
5. 图表是否漂亮
6. **最后才是**用了多少高级算法

→ 值得学的不是 DEGA/GPR/LSTM/DeepHit/LightGBM 这些名字，而是「问题一认识变量→问题二处理不确定性→问题三处理变量关系→问题四做决策→结尾敏感性证明可靠」的结构。

## 八、两条路线融合后的最强路线

```
Statistical Modeling → Predictive Modeling → Uncertainty Modeling
→ Mathematical Optimization → Decision Analysis
```
即：`数据清洗→EDA→统计关系→机制模型→Baseline→预测→不确定性建模→Scenario→优化→CVaR/Robust→多目标→敏感性→SHAP→算法对比→最终决策`

比「GA+神经网络+LightGBM+Optuna 全部堆上去」高级得多。
